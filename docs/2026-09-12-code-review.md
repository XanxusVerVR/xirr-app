# XIRR 計算機程式碼審查

- 審查日期：2026-09-12
- 審查版本：`6efcac8`
- 結果：發現 4 項待修正問題，其中 1 項 P1、3 項 P2。
- 驗證範圍：問題 1～3 已透過記憶體內轉譯並執行現有核心程式重現；問題 4 由模板確認。本次未重跑完整測試、建置或瀏覽器驗收。

## 1. [P1] 求解器過早判定收斂，回傳錯誤報酬率

位置：`src/app/core/xirr/solver.ts:38`

### 重現方式

| 項目 | 日期 | 金額 |
|---|---|---:|
| 期初部位 | 2000-01-01 | 0 |
| 資金投入 | 2024-01-01 | 1000 |
| 期末部位 | 2024-12-31 | 2000 |

實際投資期間恰為 365 天，預期 XIRR 為 **100%**，程式卻回傳約 **97.85%**。將零金額期初日期改成 `1990-01-01`，結果更降為約 **72.07%**。

### 原因與影響

以零金額期初日期作為折現基準，讓所有有效現金流折現後變得很小，觸發 NPV 容許誤差判斷，但利率尚未接近真解。合法輸入因此得到錯誤的成功結果，且單純修改沒有資金投入的期初日期就會改變報酬率。

### 修正建議與驗證

- 以有效現金流正規化計算，檢查收斂條件是否足以保證利率精度。
- 增加上述案例的回歸測試。
- 增加「插入較早的零現金流不影響結果」的性質測試。

## 2. [P2] 非法金額被當成空白列，無提示地略過

位置：`src/app/core/xirr/calculate.ts:57`

### 重現方式

1. 填入有效期初及期末部位，例如 `2024-01-01 / 1000` 與 `2024-12-31 / 1100`。
2. 資金進出列日期留空，金額輸入 `abc`、`-` 或 `1,000`。
3. 按下計算。

預期應提示該列日期及金額有問題；實際上該列被略過，計算回傳成功。

### 原因與影響

無法解析的金額會轉成 `amount: null`，但 `amountText` 仍有內容。`isBlankRow()` 只檢查日期與解析值，因此將有輸入內容的列誤認為空白列，使用者不會得知該筆資料未參與計算。

### 修正建議與驗證

- 空白列判斷應包含原始輸入文字，讓有內容但解析失敗的列進入驗證流程。
- 測試真正空白的列仍可略過，而日期留空且金額文字非法的列必須阻擋計算。

## 3. [P2] 負數期末部位被誤報為「期末為零、本金全損」

位置：`src/app/core/xirr/calculate.ts:108`、`src/app/core/xirr/validate.ts:28`

### 重現方式

| 項目 | 日期 | 金額 |
|---|---|---:|
| 期初部位 | 2024-01-01 | 1000 |
| 期末部位 | 2024-12-31 | -500 |

不填資金進出。程式回傳成功、XIRR **−100%**，並顯示「期末部位為 0」的本金全損註記，但當前部位實際顯示 **−500**。

### 原因與影響

目前驗證接受負數部位，全損分支又只檢查是否沒有正現金流，導致負數期末部位被套用期末歸零的特判，結果及說明互相矛盾。

### 修正建議與驗證

- 明確定義是否支援負數部位：若不支援就阻擋；若支援，也不能套用期末歸零的特判。
- 增加負數期末部位的回歸測試，確認不會回傳上述錯誤成功結果。
- 保留合法期末歸零情境的本金全損測試。

## 4. [P2] 資金進出欄位缺少可供輔助技術識別的標籤

位置：`src/app/ui/cash-flow-table/cash-flow-table.html:24`

### 確認方式

檢查每列日期及金額輸入框：皆沒有關聯的 `<label>`、`aria-label` 或 `aria-labelledby`。上方欄名只是獨立的 `<span>`，未與輸入框建立關聯。

### 影響

使用螢幕閱讀器逐欄操作時，無法可靠識別欄位用途與所屬列。

### 修正建議與驗證

- 為各列輸入框提供包含欄位用途與列識別的標籤。
- 將錯誤訊息關聯至對應欄位。
- 驗證新增、複製與排序後的欄位標籤仍正確，並以無障礙檢查工具及螢幕閱讀器確認。
